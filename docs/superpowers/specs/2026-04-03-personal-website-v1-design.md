# 个人网站 V1 设计规格

## 1. 本轮规格目的

这份文档用于把当前已经确认的方向，整理成一个适合你 review、也适合后续 Ralph loop 长时间执行的设计规格。它不是视觉稿替代物，而是把“风格、内容、边界、实现优先级”收敛成一个足够稳定的起点。

## 2. 一句话定义

做一个首页记忆点强、作品导向明确、对招聘方友好的双语个人网站，让访问者先被气质吸引，再快速理解你的能力结构与代表项目。

当前已经确认的关键决定见 [decisions.md](/c:/Users/12067/Desktop/Vibe%20coding/personal_website_liuxin/docs/decisions.md)。

## 3. 设计主张

### 3.1 Visual Thesis

首页应该像一张未来感数字海报，但不是纯艺术海报，而是一张能把人引向作品和履历的“系统化封面”。

本轮补充：

- 整体氛围和图案语言参考 `vibe.jpg`
- 其中的 glitch / 故障感由代码实现
- hero 排版偏实验性、不完全对称

### 3.2 Content Thesis

不是把所有经历平铺上墙，而是用少量高信号内容搭起判断路径：

- 先看到身份和方向
- 再看到精选作品
- 再看到履历支撑
- 最后进入联系或 PDF

### 3.3 Interaction Thesis

V1 动效只承担三件事：

- 建立首屏存在感
- 增强作品入口的可点击感
- 强化区块之间的层级切换

如果某个动效只是“好看”，却不能提升理解或气质，就不应该进入 V1。

## 4. 页面结构建议

### 首页 `/`

首页不负责讲完全部故事，只负责建立判断框架。

建议结构：

1. Hero：姓名、定位、主视觉、主 CTA
2. Quick Routes：Work / About / Contact
3. Featured Work：3 到 4 个精选入口
4. Resume Strip：经历、技能、城市等高信号摘要
5. Final CTA：下载 PDF / 发邮件 / 去作品页

已确认的 Hero 文案：

- 主标题：`正在编制游戏梦`
- 副标题：`Liu Xin｜玩法 / 技术策划，持续探索 AI 驱动的内容生成、互动结构与游戏体验`

### Work `/work`

作品页是 `入口页`，不是素材仓库。

建议规则：

- 先按 `featured` 排序
- 明确区分 `video / document / web / archive`
- 每个项目都要有一句说明，不接受只有标题和链接
- 所有作品都进入独立详情页
- Featured 详情页更完整，次级作品详情页更简洁
- `哈迪斯系统拆解` 使用真正可交互的站内 XMind 查看器

### About `/about`

About 页是 `公开版履历`，而不是 PDF 展开。

建议结构：

- 自我介绍
- 当前关注方向
- 精炼经历
- 教育
- 技能与工具
- PDF 下载

### Contact `/contact`

Contact 页应该像一个明确、可信、安静的落点。

建议优先级：

1. 邮箱
2. 微信或手机号
3. 其他社交链接

V1 已确认：

- `/contact` 公开 `邮箱 + 微信 + 手机`
- GitHub / LinkedIn 不进入 V1

## 5. 视觉语言建议

### 核心气质

- 海报感
- 系统感
- 数字档案感
- 轻微实验性
- 招聘场景下可读

### 组成元素

- 细线与分栏
- metadata label
- 坐标、编号、时间标记
- 轻微 noise / scanline / grid
- 节制使用的蓝色或洋红强调

### 应避免的方向

- 通用 SaaS 卡片堆叠
- 过多渐变玻璃拟态
- 大量装饰性 3D
- 只有氛围没有职业信息
- 视觉非常重但 CTA 很弱

## 6. 首页内容建议

基于简历内容，首页文案和结构应该围绕下面这条主线组织：

`游戏策划 / 技术策划 / AI 工具与互动系统实践`

推荐首页高信号素材来源：

- Multi-Agent 互动游戏实践
- 奥拓盖母 AI 管线 / UGC 剧情玩法
- 网易万民长歌的系统与 AI 工作流经历

不建议首页直接出现：

- 完整游戏经历清单
- 过长履历 bullet
- 所有联系方式并列堆叠

## 7. V1 作品池建议

建议从下列项目中确认 3 到 4 个进入 Featured：

1. `AI开发模拟.mp4`
2. `玩法流程demo演示.mp4`
3. `势力 AI demo 演示.mp4`
4. `哈迪斯系统拆解.xmind`

建议排序逻辑：

- 最能代表目标岗位的项目优先
- 能体现系统思考和工程落地的项目优先
- 只保留足够强的项目，不用为了数量凑满

## 8. Remaining Review Points

- 是否接受当前文档已经具备进入 baseline commit 的成熟度
- 是否接受项目简介先由我根据文件和内容拟定初稿，再在实现中微调
- 是否接受 poster / thumbnail 在实现阶段从本地媒体自动生成或手动截帧

## 9. 对 Ralph Loop 的要求

为了让后续自动开发不返工，执行时必须遵守：

- 先做首页框架，再做视觉细节
- 先做可读结构，再上氛围层
- 任何新增依赖都要先过 RFC
- 没有确认公开的字段不得自动上线
- 文档比聊天记录更高优先级

## 10. 当前结论

这套方案已经足够进入 `文档 review -> baseline commit -> worktree 开发` 的下一阶段。  
现在最值得你做的是 review 这份规格和 `docs/content-checklist.md`，把还悬空的 5 到 6 个关键决定收掉。
